## 1. 🎯 ПАСПОРТ ИССЛЕДОВАНИЯ (по специальности 2.3.2)

### 1.1. Объект исследования
> **Вычислительные процессы генерации трёхмерных поверхностей из воксельных данных в многоядерных архитектурах общего назначения.**

### 1.2. Предмет исследования
> **Методы и алгоритмы параллельной обработки данных, обеспечивающие повышение производительности изосурфейсинга за счёт оптимизации использования вычислительных ресурсов (кэш-память, потоки, память).**

### 1.3. Направления исследований (согласно паспорту 2.3.2)

| № | Направление из паспорта | Соответствие в проекте |
|---|------------------------|----------------------|
| **4** | Теоретический анализ и экспериментальное исследование функционирования вычислительных систем | Бенчмарки производительности на различных конфигурациях CPU |
| **5** | Разработка научных методов и алгоритмов организации обработки данных, хранения и ввода-вывода информации | Оптимизация структур данных (AoS vs SoA), аллокации памяти |
| **7** | Разработка научных методов и алгоритмов организации параллельной и распределенной обработки информации, многопроцессорных, многоядерных систем | Исследование масштабируемости алгоритмов от 1 до N потоков |

### 1.4. Цель исследования
> **Повышение эффективности вычислительных процессов генерации изосурфейсов в многоядерных системах за счёт оптимизации архитектуры данных, параллелизации и использования ресурсов процессора.**

### 1.5. Задачи исследования

| № | Задача | Соответствие направлению |
|---|--------|-------------------------|
| 1 | Провести анализ существующих алгоритмов изосурфейсинга с точки зрения вычислительной сложности и требований к памяти | Направление 5 |
| 2 | Разработать методы параллельной реализации алгоритмов с минимизацией накладных расходов на синхронизацию | Направление 7 |
| 3 | Исследовать влияние архитектуры данных (AoS vs SoA) на производительность и кэш-локальность | Направление 5 |
| 4 | Провести экспериментальное исследование масштабируемости на различных процессорных архитектурах | Направление 4 |
| 5 | Разработать модель оценки эффективности параллелизации с учётом закона Амдала | Направление 7 |
| 6 | Сформулировать практические рекомендации по выбору алгоритма и архитектуры для различных классов вычислительных систем | Направление 4 |

## 2. 🔬 НАУЧНАЯ НОВИЗНА (для диссертации)

### 2.1. Формулировка новизны

1. **Впервые исследовано влияние архитектуры данных (Array of Structures vs Structure of Arrays) на производительность алгоритмов изосурфейсинга в многоядерных системах с оценкой кэш-локальности.**

2. **Получены экспериментальные данные о масштабируемости алгоритмов Marching Cubes, Dual Contouring и Surface Nets при увеличении количества вычислительных потоков от 1 до 32 на процессорных архитектурах Intel и AMD.**

3. **Предложена модель оценки эффективности параллелизации алгоритмов геометрической обработки с учётом накладных расходов на синхронизацию, доступ к памяти и закон Амдала.**

4. **Разработан метод оптимизации размещения воксельных данных в памяти, снижающий количество cache miss на X% за счёт выравнивания и префетчинга.**

### 2.2. Положения, выносимые на защиту

| № | Положение | Тип |
|---|-----------|-----|
| 1 | Метод параллельной обработки воксельных данных с динамической балансировкой нагрузки между потоками | Алгоритм |
| 2 | Модель оценки эффективности изосурфейсинга в зависимости от архитектуры CPU и размера данных | Математическая |
| 3 | Экспериментально подтверждённые зависимости производительности от числа потоков, размера чанка и структуры данных | Экспериментальная |
| 4 | Практические рекомендации по выбору алгоритма и конфигурации вычислительной системы для задач геометрической обработки | Прикладная |

## 3. 📊 ТРЕБОВАНИЯ К ЭКСПЕРИМЕНТАЛЬНОЙ ЧАСТИ

### 3.1. Конфигурации для тестирования (минимум 3 системы)

| Конфигурация | CPU | Ядра/Потоки | Кэш L3 | ОЗУ | Цель |
|--------------|-----|-------------|--------|-----|------|
| **Система A** | Intel Core i5 | 6/12 | 12 МБ | 16 ГБ | Базовая |
| **Система B** | Intel Core i9 / Xeon | 16/32 | 30 МБ | 64 ГБ | Масштабирование |
| **Система C** | AMD Ryzen 9 | 16/32 | 64 МБ | 32 ГБ | Архитектурное сравнение |

> ⚠️ **Требование ВАК:** Эксперименты должны быть воспроизводимы на различном оборудовании для подтверждения общности результатов.

### 3.2. Метрики сбора данных

| Категория | Метрика | Единица | Инструмент |
|-----------|---------|---------|------------|
| **Производительность** | Время выполнения | мс | `std::time::Instant` |
| | Пропускная способность | вокселей/сек | Расчётная |
| | Ускорение (speedup) | × (коэф.) | T₁ / Tₙ |
| | Эффективность параллелизма | % | Speedup / N × 100 |
| **Память** | Пиковое потребление | МБ | `tracemalloc` / `heaptrack` |
| | Количество аллокаций | шт. | `countme` / кастомный аллокатор |
| | Кэш-промахи (L1/L2/L3) | шт. | `perf stat` |
| **Процессор** | Утилизация ядер | % | `top` / `htop` |
| | IPC (instructions per cycle) | — | `perf stat` |
| | Тактовая частота (средняя) | ГГц | `cpufreq` |

### 3.3. План экспериментов

| № | Эксперимент | Переменные | Фиксированные параметры |
|---|-------------|------------|------------------------|
| **E1** | Strong Scaling | Потоки: 1, 2, 4, 8, 16, 32 | Размер чанка: 64³ |
| **E2** | Weak Scaling | Потоки: 1, 2, 4, 8, 16, 32 | Размер на поток: 32³ |
| **E3** | Размер данных | Чанк: 16³, 32³, 64³, 128³ | Потоки: 8 |
| **E4** | Архитектура данных | AoS vs SoA vs Hybrid | Чанк: 64³, Потоки: 8 |
| **E5** | Выравнивание | align(8), align(16), align(32) | Чанк: 64³ |
| **E6** | Алгоритмы | MC vs DC vs SN | Чанк: 64³, Потоки: 8 |
| **E7** | Процессоры | Intel vs AMD | Чанк: 64³, Потоки: 8 |
